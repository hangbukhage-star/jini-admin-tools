# 지니가 전하는 소식 — 운영 안내

운영 구성: 기존 Vercel 홈페이지에 게시판을 추가하고, Cloudflare에 게시글·사진·조회수를 저장합니다. 수집은 매일 한국 시간 오전 7시에 시작하도록 설정합니다.

## 평소 사용하는 화면

- 홈: 제목 배너 아래 최근 소식 3개. 상단 고정 글 우선, 그다음 가까운 행사순.
- `/news/`: 예정·진행 중 / 지난 소식, 분류, 상세 안내, 사진 최대 3장, 공식 링크.
- `/news/admin.html`: 혼자 관리하는 화면. 확인 대기 글 게시, 직접 글쓰기, 수정, 숨김, 상단 고정, 사이트 등록·중지, 원문 변경 확인, 자료 백업.
- 관리자 키는 브라우저에 저장하지 않으며 새로고침하면 다시 입력합니다.
- 게시글 조회수는 글을 열 때마다 1회 올라갑니다. 같은 사람이 다시 열거나 게시글 화면을 새로고침해도 포함합니다. 홈·게시판 목록만 보거나 관리자에서 글을 수정하는 것은 집계하지 않습니다. 조회수는 목록·상세·관리자에 표시하며, 제목이나 내용을 수정해도 유지됩니다. 실제 방문자 수와는 다릅니다.
- 공개 화면에서는 출처 문구 대신 무료·유료 및 금액을 표시합니다. 금액이 없는 항목은 요금 확인 필요로 안내합니다. 수집 기관·원문 링크는 관리와 갱신을 위해 내부에 유지하며 공식 안내·예매 버튼은 제공합니다.

공연·전시·세미나·문화강좌·기타 소식을 지원합니다. **수집 범위는 등록한 목록 페이지에 올라온 글**입니다. 기관의 다른 전시·교육 메뉴까지 포함하려면 그 목록 주소도 추가해야 합니다.

## 자동 수집

1. Cloudflare 예약 실행이 한국 시간 매일 오전 7시에 Vercel 수집 함수를 호출합니다. 실제 시작·완료 시각은 서비스 지연에 따라 달라질 수 있습니다.
2. Vercel에서 목록과 상세 페이지를 읽고, 제목·날짜·시간·장소·관람료·관람 대상·이미지를 정해진 규칙으로 추출합니다. 유료 AI API는 사용하지 않습니다.
3. 기존 Cloudflare D1에 저장합니다. 최초 등록은 확인 대기 상태이며, 관리자 화면에서 검증한 뒤 사이트별로 자동 게시를 켤 수 있습니다.
4. 새 글은 오늘부터 3개월 이내 시작하거나 현재 진행 중인 행사만 받습니다. 날짜가 불명확하면 대기로 들어갑니다. 날짜가 지난 글은 공개 홈에서 제외되고 지난 소식에 남습니다.
5. 이미 게시했거나 직접 수정한 내용은 덮어쓰지 않습니다. 새 원문 내용은 별도로 보관하고 관리자 화면에서 확인합니다. 숨긴 글은 자동으로 다시 공개하지 않습니다.
6. 일정·취소 등 변경은 원문을 다음에 확인했을 때 감지합니다. 실시간 예약 현황이나 매진 여부는 보장하지 않으며 공식 링크로 안내합니다.

우진은 글 게시일이 아닌 본문의 행사일을 사용합니다. 포스터에만 날짜가 있으면 자동으로 추측하지 않고 관리자가 확인합니다. 무형유산원은 현재 월부터 4개 월별 페이지를 확인합니다. 소리문화의전당은 최대 100개 항목을 한 번에 읽습니다. 우진은 최근 목록 3페이지를 읽습니다.

무료 자원과 원문 사이트 부담을 줄이기 위해 사이트당 한 실행에 최대 30개 상세 글을 확인합니다. 새 글과 오래 확인하지 않은 글부터 순환 확인하므로 최초 전체 반영·변경 감지에 여러 번 실행이 필요할 수 있습니다. 전체 실행은 4분을 기준으로 사이트별 시간을 나누며 다음 실행에서 이어 확인합니다. 현재 12개 목록까지 등록할 수 있고, 그 이상은 수집 시간과 무료 사용량을 검토해 제한을 조정해야 합니다.

## 사이트를 추가할 때

관리자 → 사이트 추가 → 이름과 **목록 페이지 주소** 입력 → 저장.

같은 기관의 같은 형식이면 기존 수집 방식을 재사용할 수 있습니다. 처음 보는 형식은 개발자가 날짜·장소 등의 위치를 한 번 맞춰야 합니다. 주소만 입력한다고 모든 홈페이지가 자동 지원되는 것은 아닙니다. 로그인·차단·사진 속 날짜·사이트 개편은 별도 대응이 필요합니다.

일반 사이트는 `config`에 CSS 선택자를 등록할 수 있습니다.

```json
{
  "links": ".event-list a.detail",
  "title": "h1.event-title",
  "date": ".event-period",
  "venue": ".event-place",
  "time": ".event-time",
  "price": ".event-price",
  "images": ".event-content img"
}
```

복잡한 기관은 `analytics/src/news-collectors.js`에 별도 수집 방식을 추가합니다. 공개 화면이나 저장 테이블을 다시 만들 필요는 없습니다.

## 사진과 무료 운영

- 자동 사진은 기관별 재게시 이용 조건을 확인하고 사이트 설정의 사진 사용 항목을 켠 경우에만 첨부됩니다. 출처 표기만으로 재게시 허락을 대신하지 않습니다.
- 자동 사진은 공식 이미지 주소를 참조합니다. 원문에서 삭제되거나 외부 연결을 막으면 사진 대신 공식 안내를 이용합니다. 외부 이미지는 백업에 파일로 포함되지 않습니다.
- 직접 사진은 브라우저에서 JPEG·최대 1,200px·180KB 이하로 줄여 D1에 저장합니다. 한 글 최대 3장, 직접 올린 사진 합계 50MB로 제한합니다.
- 미사용 사진 정리는 어떤 글이나 변경 대기 내용에서도 쓰지 않고 24시간 이상 지난 사진만 지웁니다. 사용 중인 사진은 글 수정에서 비운 뒤 정리할 수 있습니다.
- 백업은 게시글·사이트 설정·직접 첨부 사진을 JSON으로 내려받습니다. 복구는 개발자가 확인 후 처리하며 현재 관리자 화면의 자동 복원 기능은 없습니다.
- Vercel Hobby와 Cloudflare Workers/D1 Free의 무료 한도 내 운영을 전제로 합니다. 유료 플랜 전환·유료 AI·유료 사진 저장 서비스는 추가하지 않았습니다. 방문량·보관량 증가나 무료 정책 변경 시 점검해야 합니다. 무료 한도를 넘으면 기능이 제한될 수 있습니다.

## 최초 운영 연결 — 개발자용

설정할 비밀키는 두 종류입니다. 각각 무작위 32자 이상이며 소스·대화·공개 파일에 기록하지 않습니다.

| 이름 | 설정하는 곳 | 용도 |
|---|---|---|
| `NEWS_ADMIN_KEY` | Cloudflare Worker Secret + Vercel 서버 환경변수 | 관리자 인증과 수집 결과 저장 |
| `NEWS_COLLECTOR_KEY` | Cloudflare Worker Secret + Vercel 서버 환경변수 | 예약 실행 → Vercel 수집기 인증 |

Cloudflare 쪽 관리자 키와 Vercel 쪽 관리자 키는 서로 같게, 수집기 키도 두 서비스에서 같게 설정합니다. 두 종류의 키끼리는 다르게 만듭니다. `VITE_`나 `NEXT_PUBLIC_` 같은 공개 환경변수로 만들면 안 됩니다.

1. 현재 계정이 무료 플랜인지, 기존 예약 실행을 포함해 Cloudflare 무료 예약 개수 한도를 넘지 않는지 확인합니다.
2. `analytics`에서 `npm ci` 후 `npx wrangler d1 migrations apply jini-tool-stats --remote`로 새 테이블을 추가합니다. 기존 통계·댓글 테이블은 삭제하지 않습니다.
3. `npx wrangler secret put NEWS_ADMIN_KEY`, `npx wrangler secret put NEWS_COLLECTOR_KEY`로 비밀키를 입력합니다.
4. Vercel 프로젝트의 서버 환경변수에 같은 두 키를 입력합니다. 루트 `package.json`, 잠금 파일, `api/news-collect.js`, `vercel.json`을 포함하여 배포합니다. 프레임워크는 기존 정적 사이트 설정을 유지하고, 설치는 루트 `npm ci`를 사용합니다.
5. `analytics/wrangler.jsonc`의 수집기 주소와 허용 홈페이지 주소가 실제 배포와 같은지 확인하고 `npx wrangler deploy`합니다. 예약식 `0 22 * * *`는 UTC 기준이며 한국 시간 다음 날 오전 7시입니다.
6. 실제 관리자 화면에 연결해 기관별 ‘지금 확인’을 실행합니다. 대기 글의 날짜·장소·이미지 조건을 원문과 비교합니다. 원격 네트워크에서는 기관이 서버 접근을 차단할 수 있으므로 로컬 검증만으로 운영 수집 성공을 확정하지 않습니다.
7. 최소 여러 번의 정상 수집을 확인한 뒤 사이트별 자동 게시를 켭니다. 마지막 성공 시각과 오류가 관리자 화면에 표시됩니다.

원문 수집 설정에 문제가 생기면 해당 사이트의 수집만 끌 수 있습니다. 기존 게시글과 다른 도구들은 그대로 사용할 수 있습니다.

## 확인 명령

```powershell
npm --prefix analytics run check
```

Node 24 이상에서 날짜·기관별 추출·실제 SQLite 저장·비공개 보호·중복·수정 보호·수집 실패 상태 등을 검사합니다. `analytics/tests/news-preview.mjs`는 메모리 데이터만 사용하는 로컬 화면 검증용이며 실제 서비스에 글을 쓰지 않습니다.

운영 한도 확인: [Cloudflare Workers 한도](https://developers.cloudflare.com/workers/platform/limits/), [D1 무료 한도](https://developers.cloudflare.com/d1/platform/pricing/), [Vercel 함수 한도](https://vercel.com/docs/functions/limitations).
